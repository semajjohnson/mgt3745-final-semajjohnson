## Outcome

Prompts and credits used: One run of `audit.prompt.md` plus follow-up questions in the same session. No credits.

Hours: 0.7 actual, against about 2.5 estimated by hand. Net saving roughly 1.8 hours.

Verification performed: Each finding was checked against the source rather than accepted from the summary.

- `docs/JUDGMENT.md` is referenced three times in EVALS.md and once in STYLE.md, and `ls docs/` confirms it does not exist in this repository.
- `evals/pool.test.mjs` cannot run under this template: `package.json` globs `evals/**/*.test.js`, so a `.mjs` file is skipped silently. Confirmed by reading the glob against the HW5 filenames.
- PROJECT.md states the build depends on no streaming platform; FEATURES.md line 67 states "Spotify is the assumed platform." Both read directly.
- PROJECT.md has no success measures: `grep` for outcome, leading indicator, and guardrail returns nothing, and the file has four headings, none of which is a measures section.
- ARCHITECTURE.md has no diagram and no Trust Boundary section: `grep` for mermaid, a code fence, "diagram", and "trust boundary" returns nothing.

Retry: None needed.

Findings:

- **Tool finding.** The first pass measured which files mention which vendors, and I nearly read that as a map of what matters. It is not. `TOOLS.md` mentions the most vendors because it is the vendor ledger, not because it is the most exposed file. A frequency count is not a risk ranking, and the audit's Reader column, not its vendor column, is what found the dead files. Destination: this DDR.
- **Scaffold finding.** Four files in `context/` are read by nobody and referenced by nothing: `context/README.md` and four of the five `curiosity/` files. Destination: `docs/AUDIT.md`, verdicts Remove and Merge.
- **Spec finding.** FEATURES.md still names Spotify as the assumed platform, which PROJECT.md's constraint section contradicts directly. Destination: `context/FEATURES.md`, verdict Rewrite.
- **Verification finding.** An eval named in EVALS.md as evidence for three acceptance rows does not execute under this template's test glob. A skipped test reports nothing, so the scaffold would have gone on citing evidence that never ran. This is the only finding that was invisible from reading the files and required comparing EVALS.md against `package.json`. Destination: `context/EVALS.md` and the eval port.
- **What I could not verify.** The "Last changed" column reports dates from the HW5 repository, because this repository's history begins at the carry-forward commit. Those dates say when a file last changed in HW5, not how current its content is. Two files dated 2026-10-01 are in very different states of repair.
